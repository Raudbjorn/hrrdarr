# Quality profile editor

The Quality profiles workspace edits TV and movie profiles separately. It supports paginated browsing, creation from the native unsaved schema, duplication, replacement and explicit deletion. Groups and individual qualities can be reordered using keyboard-accessible buttons. Moving qualities and dissolving groups preserve their effective enabled state; removing a selected cutoff requires choosing a new cutoff. Higher-priority qualities appear later in the ordered list.

The editor uses native quality definitions for labels and domain-specific custom-format language choices. It exposes nullable size limits, upgrades, cutoff, score thresholds and each current custom format's score, including zero. Movie language starts as Original for new drafts. Sparse imported profiles retain their qualities and null policy until the user explicitly configures a policy. Missing qualities can be added individually. Unknown format references remain visible until explicitly removed or rejected by the server.

A single save submits the complete graph and policy for transactional backend validation. Errors preserve the draft. A lost or invalid response blocks further writes: refresh and reopen the saved profile, or explicitly discard the uncertain draft after checking saved state. Workspace navigation preserves the editor draft. Successful changes refresh the library profile assignment list.

There is no server revision/precondition for concurrent profile edits; another user's changes can be overwritten. Native deletion protects library assignments. Import-list and collection references are not implemented here. This does not claim full upstream UI parity, search behavior or import behavior.

Verification: `node --test frontend/tests/profile-*.test.mjs` covers cutoff identity, structural edits, effective allowed states, legacy policy preservation, sizes and API errors. `frontend/tests/quality-profiles-browser.mjs` is opt-in against an owned `library_ui_fixture` containing the profile schema/delete backend and the Vite proxy (`UI_URL=http://127.0.0.1:<port>`). It verifies actual TV/movie create/group/reorder/duplicate/delete requests, backend readback, in-use deletion, draft persistence and an injected lost-write response. It must not target production services.

Observed on 2026-09-27: both-domain browser scenario passed against the combined owned fixture; all 42 frontend tests passed; direct Svelte checking reported zero errors/warnings; production frontend build passed. The browser also toggles the last/first enabled child to verify group coherence. Fixture servers were stopped and joined. Full Rust integration and generated-contract verification remain the parent integration gate; this frontend change does not alter generated DTOs or add dependencies.

Deletion confirmation is cancelled before starting a profile or catalog read. Mutation handlers reject actions while reads are pending, and deletion requires a currently active confirmation. The browser regression holds a detail response while switching profiles and injects a failed catalog refresh; both must close the previous confirmation without deleting either profile. The held-response assertion reproduced the original race and passed after the guard fix in both domains.
