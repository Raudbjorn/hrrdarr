# History from native imports and snapshots

`GET /api/v1/history` returns a tagged `HistoryEvent` union. `origin: native_import` preserves the existing fields: operation UUID, `file_imported` event type, typed episode/movie target, domain-qualified historical file ID, source/destination paths, byte size, SHA256 and UTC import timestamp. These facts are written atomically with the native association commit and remain after file-record retirement.

`origin: source_snapshot` represents a validated source event, with composite `id: {application, fingerprint, source_id}`, typed target, semantic event type, original numeric `source_event_type`, UTC `occurred_at`, nullable source title/download ID, and nullable validated quality/revision/language facts. It contains no native file ID, source/destination path, byte count, hash or local import timestamp. Source code 6 is a TV file rename but a movie file deletion; the semantic event and original code both remain visible. Absent facts remain null. Raw `Data` stays in the private source archive, and download IDs containing URL/query/userinfo characters are archived/reported rather than exposed.

Composite identity deduplicates an exact backup reupload, including one-time activation of previously archived history. Different fingerprints lack stable source-installation identity and are separate provenance, even when numeric source IDs match. Existing core-library reconciliation can still reject a backup whose associations conflict with later local changes. Reading or activating source history launches no commands, imports or failed-download actions. There is no live-file join or calculation from mutable current metadata.

The native event timestamp marks association commit. It does not prove move-source retirement or other cleanup completed; no cleanup status is inferred from this immutable event. Paths describe the committed event and do not grant filesystem authority or assert present file existence.

## Query contract

The response is `ApiPage<HistoryEvent>` with `items`, matching `total`, `limit` and `offset`. Count and items share a read transaction. Results sort by canonical UTC event time descending. Equal times place native imports first, ordered by operation UUID descending; source events then order by application ascending, fingerprint ascending and source ID descending. This makes ties deterministic; offset pagination across separate requests is not a frozen snapshot when new imports arrive.

Supported optional query fields:

- `media_type=tv|movies`, `episode_id`, `movie_id`, `series_id`, and `season`. Season requires series; TV selectors may be combined as intersections. Movie selectors cannot be combined with TV selectors or the opposite media domain. A valid selector with no matches returns an empty page. Series and season filters use the episode's current relationship/numbering because event-time numbering is not stored.
- `from` inclusive and `to` exclusive, as RFC3339 timestamps with explicit timezone. Up to nine fractional digits are accepted; longer fractions are rejected rather than rounded. Inputs normalize to UTC with trailing fractional zeroes removed; leap seconds are rejected because this storage uses ordinary timestamp ordering. Inputs must remain within four-digit years and require `from < to` when both are provided. Fractional bounds compare correctly against both native second-precision and source fractional timestamps, including equivalent `.1` and `.100` inputs. Encode `+` in timezone offsets as `%2B` in URLs.
- `limit` 1–100, default 50; `offset` 0–10000, default zero. IDs must be positive JSON-safe integers; season may be zero. Larger histories can be narrowed with media/library/date bounds.

Unknown fields, incompatible selectors, malformed dates or invalid bounds return 400 `invalid_history_query`. Serialization above 1 MiB returns 413 `history_response_limit`; the read has a five-second deadline returning 503 `history_timeout`. Storage failures or invalid stored facts return a static 500 error, without logging paths or query values. There are no mutating history routes or implicit retention/pruning policies.

Migration 0017 added the native `(imported_at DESC, operation_id DESC)` ordering index. Migration 0018 adds immutable, separately stored snapshot event facts with composite provenance and scoped/order indices, plus a per-snapshot history activation version. Bound predicates compare normalized values directly to the indexed column. Each origin first selects at most offset + limit compact identity keys (at most 10100 per origin); the mixed page then joins at most 100 wide event records. This avoids sorting all stored paths and metadata. The matching count remains an exact filtered count in the same read transaction. Existing episode/movie indices remain available. Rust DTOs generate the committed TypeScript contract.

## Evidence and remaining scope

`tests/history_api.rs` uses actual owned HTTP imports into a scratch database for both domains, colliding target and file IDs, SHA256/size/path facts, pagination/order, domain/library/season filters, actual immutable timestamp boundaries including offsets/fractions, malformed queries, failed commit exclusion and file-record retirement. Reopening the database preserves the same history. The injected failed-history insert proves the association transaction rolls back without a successful event. Schema tests separately cover timestamp/UUID ties, actual version-16 upgrade preservation/rollback and the libSQL query plan's use of the new index.

The mixed snapshot/native HTTP regression additionally verifies both source applications, composite source ID collisions, code-6 domain differences, nullable facts/private-data exclusion, combined pagination, equal fractional date bounds, exact reupload and reopen. A supplemental synthetic source fact tied to an actual immutable native timestamp verifies cross-origin tie order without rewriting producer events. Source importer tests cover supported snapshot versions, dry runs, backfill, unsupported/orphan reporting and rollback.

The pinned Sonarr and Radarr History controllers also require other native event producers, download/event/quality/language filtering, expanded library resources, custom-format/cutoff calculations and mark-failed behavior. Those remain incomplete; unknown or unresolvable source events remain archived/reported rather than activated. The native route does not claim V3 wire compatibility, cleanup completion, full History parity or a browser workflow. No live services, production files/databases, remote topology or process-kill recovery were tested. No dependency or history mutation policy was added.
