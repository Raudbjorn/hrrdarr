# Torznab and Newznab protocol

The native provider test and search routes use the persisted provider endpoint and scoped categories. Implemented independently from the [Newznab Web API](https://newznab.readthedocs.io/en/latest/misc/api.html) and [Torznab 1.3 draft](https://torznab.github.io/spec-1.3-draft/torznab/Specification-v1.3.html). The latter is a draft, not a claim of certification. No reference implementation was copied or translated.

`POST /api/v1/providers/{id}/test` fetches capabilities and then authenticated, category-scoped RSS for **each** configured domain. Public capabilities alone do not establish authentication. Empty successful feeds are valid evidence of access, not evidence that content exists. A failed domain fails the test. The surrounding provider API owns revision checks and persistent test status.

`POST /api/v1/providers/{id}/search` accepts `IndexerSearch`, a closed `kind` union:

- `rss`: required `media_type` (`tv` or `movies`). TV RSS combines normal and anime categories.
- `tv`: required `title` and `numbering`; optional nullable `tvdb_id`, `tvmaze_id`, `rage_id`, `imdb_id`, `tmdb_id`. Numbering is `episode` (season/episode, including season zero), `season` (pack), `daily` (strict calendar date `YYYY-MM-DD`), `daily_season` (year), `special` (episode title), `anime` (absolute episode and optional positive season/episode pair), or `anime_season` (positive season and up to 16 season-specific aliases). TV `search_mode` defaults to `default` (ID search then empty-result title fallback); `ids`, `titles`, and `both` select the corresponding query families. Anime searches ignore this mode and run their complete query sequence.
- `movie`: required `title`; optional nullable `year`, `imdb_id`, `tmdb_id`.

TV/movie requests also accept up to 16 aliases, each 1–512 UTF-8 bytes without control characters. Duplicate aliases and aliases equal to the primary title produce no duplicate query. Search-engine normalization applies to these supplied titles as described below.

All modes accept optional `offset` (default zero) and `limit` (default 100, accepted 1–500). Offset is a zero-based unsigned 32-bit integer; the effective limit is capped by advertised capabilities. One response returns one page from one query. Optional `query_index` defaults to zero and must select an existing planned query. The response includes the actual `query_index`, `query_count` and nullable `next_query: {query_index, offset}`. Continue with both cursor values, retaining the same request and provider revision. `next_offset` describes only the current remote query; use `next_query` to traverse aliases. Counts and totals describe individual queries, never an invented union count. The same release can occur on several alias pages; internal GUIDs remain available to the future search collector for deduplication.

An empty first ID page advances to the title family and skips empty aliases within the current operation deadline. Authentication, transport, XML and other errors never trigger fallback. Nonzero offsets never silently switch queries. Successful ID pages continue that ID query and then stop for default TV/movie searches. TV `both` and anime instead continue their remaining same-tier queries. Explicit query cursors can also select a title query directly. There are at most 35 ordinary TV queries (one ID query plus original and cleaned title variants), 18 movie queries, 70 anime episode queries, or 67 anime season queries. Query text is capped at 8192 bytes; original title/alias inputs remain capped at 512 bytes. Every request retains the transport's 30-second total deadline, one-provider lease and pacing; exhaustion returns an error, not a claimed complete result.

`total` is nullable when no protocol response count exists. Incorrect response offsets, duplicate response elements, oversized pages, impossible counts and empty pages claiming remaining results fail explicitly. Capabilities and remote feeds can change between calls; cursors are not server-side snapshots, and callers should restart traversal after configuration/capability changes.

Capabilities declare available search modes, supported parameters, maximum/default page sizes and category IDs with parent relationships. An absent domain or empty applicable category list fails without broadening the request. TV uses configured categories even when they are not advertised. Movie requests require at least one advertised selected category; a mixed supported/unsupported selection remains intact. Empty movie category advertisements therefore cannot pass a movie provider test. Custom signed-32-bit category IDs are supported exactly as configured. Category matching and release acceptance remain downstream decisions; a response's requested domain does not assert that its releases belong to that domain.

Missing limits use 100/100. Malformed or incomplete limit attributes fall back to the complete legacy capability set with no advertised categories, matching the pinned compatibility contract. Nonpositive limits and default limits above the maximum are explicitly rejected as invalid bounds. Missing `searching` uses legacy available search modes; a missing mode inside a present `searching` section disables only that mode.

Each domain negotiates aggregate IDs from its own explicit `supportedParams` advertisement. Supported supplied identifiers are sent together; movie capabilities do not enable TV aggregation. Legacy TV advertisements without that attribute use q/TVRage/season/episode defaults; legacy movie advertisements use their documented IMDb/title/year defaults. Without aggregation TV priority is TVDb, IMDb, TVRage, TVMaze, TMDb; movie priority is TMDb then IMDb. TV IMDb retains `tt`; movie IMDb sends digits only. These are compatibility requirements observed in the pinned reference capability/request contracts, not copied implementations.

Structured TV title queries prefer advertised `title`, then `q`; unsupported complete selectors fall back to generic title+numbering queries. Daily episodes use the year in `season` and `MM/DD` in `ep`. Specials use series plus episode title. Movie title fallback uses generic search and year; `remove_year=true` omits the year from that query. Movie title fallback still requires a supplied valid year. Episode/season selectors remain capability-gated. Season zero is encoded as `00` for both episode and season-pack requests, preserving compatibility with providers that treat plain zero as an absent selector.

Anime episode ID queries include a padded absolute-number `q`; title queries include the title plus that number. With `anime_standard_format_search=true` and a supplied positive season/episode pair, additional standard ID/title queries use anime categories. Successful anime ID results do not suppress these queries. Anime-season aliases are searched without an added season suffix; when the flag is true, supported IDs and regular series aliases additionally use structured `tvsearch` with the season selector and anime categories. A regular alias matching a season alias case-insensitively remains bare and is not also season-restricted. Both persisted flags default to false.

Private additional parameters come from the encrypted `indexer` credential variant, independently for TV and movies. Capabilities receive the API key only; scoped RSS and search requests append only their domain's private parameters. Shared validation rejects reserved control/category/identity/paging names, duplicate names, oversized values and malformed names. Public metadata redacts all nonempty credential parameter values and API keys; empty values do not cause empty-string replacement. No parameter values are added to public capabilities, cursor metadata or error messages.

Search engines are a closed `raw`/`sphinx` capability for each mode; missing or unknown engine names use Sphinx and never echo server text. Movie fallback uses the generic search engine. Sphinx title cleanup removes leading “The ”, apostrophe/period/accent-quote characters and Unicode nonspacing accent marks, replaces `&` with `and`, separates other punctuation and collapses whitespace; underscores remain word characters. For example, `The Café’s & Co.` becomes `Cafes and Co`, while `A&B` becomes `AandB`. ICU canonical decomposition and recomposition preserve other Unicode text. TV raw q searches include original and cleaned title variants; movie raw searches use originals only. Literal plus signs become spaces in q text. TV's dedicated `title` parameter keeps the original title and does not add cleaned variants. Empty cleaned titles cannot turn into suffix-only or year-only searches.

There is no automatic retry, scheduler, durable RSS cursor, grab or download in these routes. Those operations and downstream release matching/decisions remain separate delivery requirements.

XML uses pinned `roxmltree 0.21.1` with no entity resolver, DTD entity declarations disabled, 20,000 nodes and a 1 MiB input ceiling. RSS extensions are recognized by the Newznab/Torznab namespace URI, regardless of prefix. Repeated attributes retain distinct values; conflicting singular numeric attributes fail. Publication date and a usable acquisition locator are required. Missing optional titles, GUIDs and sizes stay absent; missing categories produce an empty list. Private GUID absence is not replaced with an invented identity. Titles receive one HTML-entity decoding pass after XML decoding, including CDATA, followed by size/control validation and credential redaction; decoding does not iterate to a fixed point. A valid size attribute wins over enclosure length; invalid size can fall back to valid enclosure length. If supplied size values are all invalid, the item is rejected rather than represented as unknown. Newznab `usenetdate` takes precedence over `pubDate`; Torznab uses `pubDate`. Accepted dates are RFC2822, RFC3339 and ISO calendar dates (midnight UTC); output is UTC. Missing or invalid mandatory dates fail the feed.

Other malformed items and duplicate known GUIDs are rejected with bounded `warnings: [{index, code: "invalid_item"}]`. Index is the absolute remote result position (`requested offset + raw item position`), and paging advances by raw item count, not the number retained. Warnings disclose no rejected content. A wholly rejected nonempty page fails rather than pretending to be a valid empty RSS result. Warning causes include invalid locators, malformed optional typed attributes, contradictory singular values, wrong-protocol-only enclosures and duplicate known GUIDs.

Up to 16 enclosures per item are inspected. Matching normal NZB/torrent MIME is preferred, then the compound torrent magnet MIME `application/x-bittorrent;x-scheme-handler/magnet`, then unknown MIME. Wrong-protocol-only enclosures fail the item. HTTP(S) acquisition URLs forbid user information; torrent magnet fallback requires a torrent `xt` identifier. Acquisition URLs are retained privately and never fetched here.

Attribute names are case-insensitive. Repeated language attributes or bare language elements are preserved; Newznab additionally splits comma-delimited languages. Explicit peers win, otherwise seeders plus leechers derive peers without overflow. Private facts retain media-scoped TV/movie identifiers, scene/nuked/subtitle flags, comments/info links, torrent hashes/magnets, seeding minima and volume factors. Scene evidence includes `prematch`/`haspretime`; scene/internal tags are case-insensitive. Missing, zero or invalid optional response IDs remain absent without discarding the release; numeric IMDb IDs are formatted with `tt` and at least seven digits. Request ID validation remains strict. Native IMDb response parsing accepts up to ten digits, a bounded extension beyond the pinned integer parser, while preserving the seven-digit minimum display form. An absent explicit info URL can derive from the private comments URL by removing a trailing `#comments`. These transport facts are not a downstream acceptance decision.

Public results contain nullable title and byte size, normalized publication date, numeric categories, nullable torrent peer counts, languages and paging metadata. Size is restricted to the JavaScript exact integer range. GUIDs, acquisition URLs and raw attributes remain internal Rust values without `Serialize` or `Debug`, because indexers can embed passkeys in them. Known API-key and private-parameter text is also redacted from public title/language fields. Capabilities expose only recognized parameter names, never arbitrary server description text. XML and network errors never expose remote descriptions or response bodies. XML codes 100–199 classify authentication, 203 unsupported, and 429/500 rate limiting. A request-limit description also classifies rate limiting; without an API key, missing-parameter/API-key descriptions classify authentication even for generic parameter codes. Other protocol errors remain invalid responses. Rate-limit errors enter the shared transport cooldown rather than retrying immediately.

`tests/indexer_protocol.rs` covers both protocols' planned requests, aggregate/legacy capabilities, scoped modes and persisted flags, empty-ID fallback, aliases, explicit query/page continuation, no fallback on errors or nonzero offsets, private parameter encoding/redaction, namespaces, duplicate attributes, integer/date validation, MIME mismatch, malformed XML/DTD, paging, and real requests to an owned `127.0.0.1:0` fixture server. Provider API integration has separate revision/status tests. Recorded synthetic fixtures establish the tested wire behavior, not runtime equivalence to every deployed indexer version. No operator services, credentials or accounts are used. Jackett/Prowlarr can expose a compatible Torznab endpoint; this does not establish separate Jackett configuration or provider parity.

Normalization reuses the already locked `icu_normalizer` and `icu_properties` 2.3.0 dependencies with compiled data; no new crate versions were introduced. The [Sphinx query syntax](https://sphinxsearch.com/docs/current/extended-syntax.html) explains why punctuation is semantically significant. Compatibility cases listed here are explicit fixture evidence; they do not establish behavior of every vendor deployment or complete Sonarr/Radarr automation.

HTML title decoding uses pinned `html-escape 0.2.15`, a dependency without runtime dependencies. Both raw and normalized title queries reject whitespace-only title content; no suffix/year-only query is substituted.
