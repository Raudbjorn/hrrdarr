# Native health engine

Health checks share the existing single, locally owned command worker. Cached observations are persisted separately from processing authority. A health warning never disables completed-download handling. The registry contains TV and movie `completed_download_handling` and `download_client_communication` checks; see [detector behavior and transport limits](health-detectors.md). Other health catalog entries and notification delivery remain incomplete.

`GET /api/v1/health` reads a transactionally consistent cached snapshot, without client/network probes. `scope` accepts `all`, `tv`, `movies`, or `system`; `limit` is 1–16 (default 16), `offset` 0–127. Check states distinguish never evaluated, pending, running, stale, failed, and current observations. The summary covers the entire requested scope, independently of pagination. An empty issues page therefore does not assert that checks succeeded. Coverage describes only registered identities. Previously observed issues remain visible during failed or pending rechecks.

`POST /api/v1/health/commands` requires `{ "scope": "all", "priority": "normal" }` (or priority `high`), rejects unknown fields, and returns 202. The response distinguishes a new queued batch, union into an unclaimed batch, and pending selection tokens behind a running/retrying batch. Tokens identify the requested generations; a running command ID does not promise coverage of a later request. Unregistered scopes return 409. One global active health batch participates in the shared 1,024-active-command pool; no fictitious media ID is assigned. A manual admission rejected for capacity rolls back its markers. Automatic markers remain durable for later admission.

`GET /api/v1/health/commands` supports scope, status, limit (default 20, max 100), and offset (max 128). Scope matches membership, including coalesced multi-domain batches. `GET /api/v1/health/commands/{uuid}` returns the full bounded membership. `POST /api/v1/health/commands/{uuid}/cancel` accepts an empty body/query and cancels the **whole batch**, including coalesced requests. Cancellation preserves observations and newer generations. Repeating cancellation on a retained terminal command is idempotent. The newest 128 terminal commands are retained; an unknown or pruned ID is 404, never implied success. Retained history pagination can drift as history is pruned.

Startup starts a new persisted epoch and marks startup checks immediately due. A six-hour schedule survives restart. Configuration mutations persist dirty generations in the same transaction as authority changes, including equal-value explicit CDH saves and download-client create/update/delete/import/bulk changes. Configuration-only work uses a five-second trailing debounce; manual/startup/scheduled/grace work is never postponed by a later configuration change. Provider configuration selects both checks; CDH master saves select CDH alone. Committed current-revision provider-test changes and refresh outcomes select communication only in the same transaction. Concurrent tests deduplicate normalized outcome changes. Status markers use a non-postponing five-second due time; repeated refreshes cannot move the deadline, and the sole worker cannot refresh concurrently with its own health probe. Automatic status generation exhaustion retains the authoritative status and records `health_invariant`; general storage errors still roll back. A queued batch may gain membership; retries retain their original membership and three-attempt budget while capturing fresh generations.

Selected evaluations run outside writer transactions, with a 30-second whole-batch deadline and 250 ms cancellation polling. Publication atomically verifies command ID, running status, attempt, epoch, and every selected generation. Stale inputs publish nothing and preserve newer work. Each attempt publishes completed observations and unevaluated errors together in one transaction. Unevaluated members retain their previous issue and observation; completed members may expose a communication Error even when another member could not run. Mixed attempts remain failed/retrying, never a successful whole batch. All frozen members keep their markers through retries; terminal settlement clears only matching generations (only the grace bit after grace exhaustion). A failed member cannot overwrite a successful member’s error state. The aggregate deadline retains already completed outcomes and marks current/unvisited members unevaluated. Communication probes run first to avoid losing a fresh remote failure to a CDH-created transport cooldown; cached cooldown remains unevaluated. Existing 45-second worker timeout/error recovery also recovers health work. No detector tasks are detached.

Initial failures are visible immediately. For the first 15 minutes, issue/restored transitions are marked in-grace. At the deadline, one durable full-startup recheck must evaluate every member before grace expires. Partial results stay in grace without final announcements or advancing the last successful batch timestamp. It first applies results while still in-grace, then announces every remaining cached issue once outside grace. A restored transition contains the latest **previous issue** payload. Repeated or changed failures update observations without repeated issue transitions. An exhausted/cancelled grace run schedules another attempt after 60 seconds. Old-epoch grace work cannot expire a new process's grace. This timed, persisted lifecycle is a native adaptation of upstream event-driven grace handling.

`GET /api/v1/health/transitions?after_sequence=0&limit=16` exposes the newest 1,024 diagnostic transitions using monotonic safe-integer sequence IDs. It returns oldest/latest retained sequence, next cursor, and an explicit retention-gap flag. Transition identity includes the command attempt, allowing legitimate issue → restored → issue across retries without dropping the third event. Historical events preserve unknown attempt provenance internally. Sequence exhaustion fails publication transactionally; it never wraps. Automatic generation exhaustion records `health_invariant` in the lifecycle without blocking unrelated commands in the shared worker; manual/configuration mutations fail rather than wrap or commit an unmarked change. Responses are bounded to 1 MiB. This journal is **not an acknowledged delivery outbox**: no script, email, webhook, notification routing, provider retry, or external exactly-once delivery is claimed. A delivery consumer must establish its own durable ownership before relying on retention.

Focused evidence lives in `src/health/tests.rs` and `tests/health_engine.rs`: deterministic lifecycle/capacity/fencing/grace/recovery checks, bounded real HTTP probes, and real API plus owned-worker flows. Tests use temporary databases and owned loopback peers only. Full integration verification and UI consumption are separate; no live-provider or performance equivalence is claimed.

## Native Health workspace

The lazy-mounted Health workspace reads cached scoped coverage, lifecycle, current check states, retained command membership/details and global diagnostic transitions. Polling is chained at five seconds only while the workspace and document are visible; stale in-flight reads are discarded. Read failures retain explicitly labelled old content. Summary counters overlap, and an empty registry or empty page never implies system health. Help links allow only HTTP(S), and messages render as text.

Manual requests retain up to eight generation selections while the workspace remains mounted. Only current, error-free observations in the current epoch and on the observed page can verify those tokens. Other scopes/pages remain unverified. Dismissing tracking or navigating away does not cancel work. Lost mutation responses have an explicit unknown-outcome barrier and are never automatically retried. Whole-batch cancellation requires confirmation naming the batch and members; newer pending generations and previous observations remain. Unknown/pruned detail is not cancellation success.

Both registered completed-download checks link to Activity's existing domain editor. Navigation waits for busy reads/writes, preserves dirty-draft confirmation and refuses unresolved write outcomes. Navigation itself never saves a setting; an explicit equal-true save can record the TV choice. No scheduler editor, notification delivery or other System surfaces are implied.

Runnable UI checks: `npm --prefix frontend test`, `npm --prefix frontend run check`, `npm --prefix frontend run build`, and `frontend/tests/health-browser.mjs` against the explicitly started ignored `library_ui_fixture` and Vite proxy. Browser environment: `UI_URL`, `UI_PROVIDER_ORIGIN`, optional `PLAYWRIGHT_MODULE` and `PLAYWRIGHT_EXECUTABLE`. The fixture owns temporary storage and ephemeral loopback servers; its mode 3 delays preferences eight seconds to exercise real pending generations/cancellation. Browser response overlays establish UI rendering/race behavior only, not detector or upstream equivalence. Existing completed-download and library browser regressions remain separate checks.
