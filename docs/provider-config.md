# Native provider configuration

The first provider foundation stores Torznab, Newznab and qBittorrent configuration for TV, movies, or both. Saving it does not contact the endpoint. Torznab/Newznab now provide capability negotiation, explicit tests and scoped metadata searches; full controllers and download/grab workflows remain incomplete.

## HTTP contract

| Method and route | Contract |
| --- | --- |
| `GET /api/v1/providers` | `ProviderQuery`: limit defaults to 50 (1–100), offset defaults to 0, optional `media_type=tv|movies`. Returns `ApiPage<Provider>`, ordered by priority, name, UUID. |
| `POST /api/v1/providers` | `ProviderInput`; creates revision 1, returns 201 and the stored public provider. |
| `GET /api/v1/providers/{uuid}` | Returns the public provider or 404. |
| `PUT /api/v1/providers/{uuid}` | `ProviderUpdate`: full configuration plus current revision. Returns the stored next revision; stale revision or changed implementation returns 409. |
| `DELETE /api/v1/providers/{uuid}?revision=N` | Explicit configuration deletion with revision check; returns 204. This does not delete media or client downloads. |
| `POST /api/v1/providers/{uuid}/test` | Torznab/Newznab: performs capabilities and scoped feed probes, returns `ProviderTestResult` with provider/revision/time/result. qBittorrent remains 501 `provider_test_not_implemented`. |
| `POST /api/v1/providers/{uuid}/search` | `IndexerSearch` selects RSS, TV numbering or movie identity explicitly. Returns `ProviderSearchResult` with provider/revision and a metadata page. No grab or client submission. |

`ProviderSettings` is a closed implementation-tagged union. `endpoint`, `tv` and `movies` are required; absent scopes are explicit `null`, and at least one scope must exist. Torznab and Newznab TV settings contain `categories` and `anime_categories`; movies contain `categories`. Each list holds at most 64 distinct positive signed-32-bit IDs. Movie categories and the combined TV categories must be nonempty. These are configured category IDs, not negotiated capabilities. TV additionally persists `anime_standard_format_search`, and movies persist `remove_year`; both default to false when omitted and are returned explicitly in public settings. Migration 0011 backfills false without invalidating existing test observations because this preserves prior behavior. TV SearchMode belongs to a search request rather than provider configuration.

qBittorrent scopes contain `category`, nullable `imported_category`, `recent_priority` and `older_priority`. Category names are 1–64 UTF-8 bytes without control characters, backslashes, doubled slashes or leading/trailing slashes; nested single slashes are supported. Active and imported categories must differ within a scope and between TV/movie scopes. Priorities are exactly 0 (Last) or 1 (First), matching the pinned references' `QBittorrentPriority` enum. Other provider priority concepts are not interchangeable. The top-level priority is 1–100, name 1–128 UTF-8 bytes and enabled is explicit. Disabling preserves settings and credentials.

Endpoints are HTTP(S) URLs, at most 2048 UTF-8 bytes, with a host and no user info, query, fragment, control characters, raw backslashes or surrounding whitespace. The configured endpoint path is public: put credentials in the credential field, never in a path. No TLS bypass, redirects, proxy or network reachability is inferred by saving a URL.

Requests are capped at 32 KiB; responses at 1 MiB. Bounded scopes and pages also bound in-memory reads. Reads use a consistent database transaction. Mutations atomically update the provider, encrypted credentials and scopes, construct/check the public response before commit, and explicitly roll back errors. Stored implementation, identity and settings version cannot change. Revision increments exactly once; update rejects unsafe JavaScript integer revisions and exhaustion. SQL failures log a random correlation ID and error variant only, without parameters or error text. Public validation/database/credential errors are static and never include submitted JSON or provider responses.

Public responses contain `has_credentials`, implementation-specific `test_supported`, `test_status` (`never_tested`, `success`, `failure`) and nullable `last_test` (revision, Unix timestamp seconds, outcome, static error code). They never contain credential ciphertext or plaintext. A completed test is an observation of that configuration revision, not ongoing health or proof of download/search parity. Configuration changes atomically invalidate previous observations. Settings and queries are generated from Rust in `frontend/src/lib/api.generated.ts`; unknown input fields are rejected.

## Credentials and key recovery

Credentials are write-only `{"kind":"api_key","api_key":"..."}` or, for qBittorrent only, `{"kind":"username_password","username":"...","password":"..."}`. The alternatives cannot be combined. Strings are nonempty, have no control characters and are at most 4096 UTF-8 bytes each; the serialized secret also must fit the encrypted envelope. Omitted credentials preserve the existing ciphertext, explicit `null` clears it, and an object replaces it. Indexers additionally accept a private bundle described below; the existing API-key variant and ciphertext remain readable. A configuration without credentials can be stored; this is not an assertion that anonymous authentication works.

Supply `HRRDARR_PROVIDER_KEY` through the service's protected secret facility as exactly 64 hexadecimal characters encoding 32 cryptographically random bytes. Generate it once using an OS cryptographic random source; never use a password or commit it. The application never generates, persists, returns or logs this key. A malformed supplied environment value stops startup with a static error. An absent key allows redacted reads and credential-free configuration, but cannot save a new secret or mutate/delete any credential-bearing record. A wrong key or corrupted envelope likewise prevents mutation, including replacement and clearing, preserving recoverability with the correct key.

Existing ring 0.17.14 AES-256-GCM encrypts the complete typed credential value with a fresh random 96-bit nonce. Envelope version 1 is `version-byte || nonce || ciphertext-and-tag`, bounded to 16 KiB. Authenticated associated data binds the envelope to its provider UUID, implementation and credential format version. Copying ciphertext to another provider or changing implementation therefore cannot unlock it. Key material and plaintext necessarily exist in process memory; this is encryption at rest, not memory-dump protection or protection from the running service account.

Back up the deployment key independently using the operator's protected secret backup process. A database backup contains encrypted provider credentials but **does not contain this key**. Restore requires the matching key. Keep a recovery copy before changing service environment settings; on key mismatch restore the original key rather than recreating provider definitions. There is no key rotation/re-encryption endpoint in this foundation: changing the environment key is not rotation and locks existing rows. Any future rotation must decrypt and re-encrypt all rows transactionally and retain independent recovery material. Existing archived snapshot provider settings are not activated or rewritten by this API; those private archives may contain plaintext and still require their existing storage protections.

## Evidence and limits

`src/providers/credentials.rs` tests fresh nonces, decrypt roundtrip, wrong-key failure, tampering, unknown envelope versions and provider/implementation binding. `tests/provider_config_api.rs` exercises real temporary HTTP endpoints and databases for both domains, credential omission/replacement/clearing, static error redaction, revision conflicts, failed-write rollback and key-loss behavior. Migration tests cover schema8 upgrade/reopen and SQL constraints. No live services, accounts or real media are used.

This does not prove remote libSQL transport recovery, production backup/key custody, authentication of hrrdarr itself, live-provider equivalence, browser workflows or full Sonarr/Radarr parity. Endpoint configuration alone is local validation only. There is no scheduled health engine, factory for unavailable providers, snapshot provider activation or unused family trait.

Dependencies: existing [ring AEAD API](https://docs.rs/ring/0.17.14/ring/aead/) and newly pinned [url 2.5.8](https://docs.rs/url/2.5.8/url/) for standard URL parsing. Cargo.lock adds url and its IDNA/Unicode dependency graph (25 packages); existing locked package versions remain unchanged. The concrete indexer transport additionally pins reqwest 0.13.5 (defaults disabled, rustls enabled) and roxmltree 0.21.1, adding 48 locked packages without changing existing package versions. Existing Tokio explicitly enables sync/time/io-util for transport bounds and isolated streaming tests.


## Concrete indexer transport and observations

A reused [reqwest 0.13.5 client](https://docs.rs/reqwest/0.13.5/reqwest/struct.ClientBuilder.html) validates TLS using platform roots, disables proxies (including environment proxies), redirects, automatic retries, referer and cookies. It requests identity encoding and rejects compressed responses instead of performing unbounded decompression. Streaming reads stop above 1 MiB, including chunked bodies without Content-Length. Neither reqwest errors, URLs nor upstream response/error bodies are formatted in public errors or logs. Test completion logs contain only a correlation ID, provider UUID, revision and static outcome/code.

At most eight provider operations run simultaneously and one per provider; admission returns `provider_busy` rather than queuing unbounded waiters. Each admitted operation holds its permits through the final revision check/status write. Requests within an operation start at least 100 ms apart. Each request has 3-second connection, 5-second read-stall and 10-second total limits. All HTTP work shares a 25-second budget, reserving five seconds of the 30-second operation deadline for final database work. Cancelling/dropping an operation releases its permits. The connection pool retains at most two idle connections per host for 30 seconds.

The per-provider limiter retains at most 256 identities and expires inactive entries after 60 seconds unless a cooldown remains. HTTP 429 supports numeric or RFC2822 HTTP-date `Retry-After`; XML rate-limit errors share the same mechanism. Cooldowns default to 60 seconds when no valid hint is supplied and are bounded to 1–86400 seconds. API rate-limit failures return a `Retry-After` header. No request is retried automatically. Cooldown/admission state is in memory and resets on application restart; durable scheduler/backoff behavior remains later work. Unrelated providers may use available lanes while one provider cools down.

Test/search reads a consistent configuration snapshot and decrypts its credentials once, then closes the read transaction before contacting the endpoint. Tests persist only timestamp/outcome/static code using an atomic current-revision predicate; edits/deletion during network work return 409 and cannot mark the new configuration tested. Searches also reject stale snapshots and return the revision with their results. Tests intentionally work on disabled providers for setup; explicit search is also user-invoked and does not start background automation. A successful manual search does not overwrite the last explicit test observation. Request cancellation/deadline expiration may leave the preceding completed observation; the status is not a claim that an in-flight test finished.

Provider-returned download locators, opaque GUIDs and arbitrary attributes stay out of public results because they may contain API keys or tracker passkeys. The native search page contains metadata only and is not a grab token. Protocol fields, capability fallback and XML security limits are documented in [indexer-protocol.md](indexer-protocol.md). Parser configuration uses [roxmltree 0.21.1](https://docs.rs/roxmltree/0.21.1/roxmltree/struct.ParsingOptions.html) with DTD/external entity resolution disabled and bounded nodes.

`src/providers/http.rs` has owned-loopback checks for redirects, encoded/oversized/chunked responses, deadlines, cancelled leases, concurrency and cooldowns. `tests/provider_indexer_api.rs` verifies concrete test/search/status integration and stale revisions with owned temporary HTTP servers. Production services and credentials were not used.


## Private additional indexer parameters

`{"kind":"indexer","api_key":null,"tv_parameters":[{"name":"passkey","value":"private value"}],"movie_parameters":[]}` is an additional write-only credential variant for Torznab/Newznab. API key omission/null means no key; parameter lists default empty. At least one key or parameter must exist in a stored bundle. It uses the same authenticated encryption envelope and omitted/preserve, null/clear, whole-object replacement semantics as existing credentials. `has_credentials` means an encrypted private bundle is present, including bundles with parameters but no API key; it does not assert that an API key is configured.

Parameter names and values are never included in public configuration, debug output or errors. There are at most 16 parameters per domain; names are ASCII identifiers of at most 64 bytes, beginning with a letter and containing letters, digits, underscore, hyphen or dot. Values are at most 1024 UTF-8 bytes without controls; empty values are allowed. The entire serialized credential bundle must still fit the existing 16 KiB envelope. Case-insensitive duplicate names and protocol-owned names (authentication, action, categories, media IDs, title/year/numbering, pagination and response format) are rejected. This reserved-name rule is a native safety constraint, stricter than upstream raw-string query appending.

The transport percent-encodes each private value as one query value. Only the requested media domain's parameters are appended to RSS/search calls. Shared capability discovery receives the API key but no domain-specific parameters. A provider requiring private parameters to expose its capability endpoint is therefore not supported by this contract. Values associated with an inactive domain are retained encrypted and dormant, allowing later re-enabling without losing private settings; they are never sent for another domain. Public result strings redact nonempty known private values as well as the API key. Empty parameter values do not participate in redaction.

Unit checks cover reserved/case-duplicate/size rejection and old/new encrypted payload roundtrips. The configuration HTTP test verifies additive defaults and flags, encrypted parameters without public name/value disclosure, exact ciphertext preservation on omission, and missing/wrong-key refusal for the new variant. The protocol fixture test exercises scoped parameter encoding and public result redaction.

Search pagination includes query selection as well as offset. Callers must retain the same search request, follow its returned query/offset cursor, and reject pages with a changed provider revision. The server's final revision check detects changes during one request; it does not pin configuration or discovered capabilities across several pages. There is no stored search session or capability snapshot cursor yet, so consumers must not combine results across a detected revision/capability change.

Unicode search normalization directly uses `icu_normalizer = 2.3.0` and `icu_properties = 2.3.0`, with default features disabled and `compiled_data` enabled. These exact crates and data packages were already locked and installed through URL/IDNA support. The promotion adds only two direct dependency edges to the hrrdarr package; the lockfile comparison added, removed or upgraded no packages. Versions/features were checked against the installed registry crate manifests and [Cargo.lock](../Cargo.lock), and the updated [Cargo.toml](../Cargo.toml) resolved and checked offline. The protocol implementation uses canonical decomposition and the Unicode nonspacing-mark category rather than a hand-maintained accent table.

Search capability responses identify the declared `raw` or `sphinx` engine. Public release metadata represents unavailable title/size as `null`. A page can include `warnings` with `code: "invalid_item"` and an absolute index into the remote result stream; private release facts remain outside the generated/public contract. Consumers must retain these warnings and use the returned continuation rather than deriving pagination from the number of successfully parsed items.

RSS title processing additionally uses pinned `html-escape = 0.2.15` with default features disabled. The registry identifies Rust 1.58 as its minimum version; its installed manifest declares no runtime dependencies. This adds exactly one locked package and no upgrades or downgrades. [`decode_html_entities`](https://docs.rs/html-escape/0.2.15/html_escape/fn.decode_html_entities.html) performs one HTML-entity decoding pass after XML decoding, covering named, decimal and hexadecimal references without a project-maintained entity table. The decoded value remains text, with validation and private-value redaction applied afterward; it is not recursively decoded or interpreted as markup.
