# Release profile settings

The native `/api/v1/{tv|movies}/release-profiles` API stores a set of restrictions. Every applicable enabled profile is selected; there is no priority order or fallback profile. The Profiles → Release profiles editor exposes both domains. Decision enforcement is separate integration work.

GET returns a catalog with a domain revision and profiles. GET `/schema` returns a draft, which may be invalid until a term or TV-specific rule is added. GET `/{id}` includes the catalog revision. POST and PUT `/{id}` accept `{revision, profile}`; DELETE `/{id}?revision=...` also checks that revision. Successful mutations return the complete catalog. A stale revision returns 409 without changing data. Every accepted native mutation records local intent and atomically wakes resumable same-domain pending candidates; prepared/submitting/reconciling ownership remains unchanged.

Both domains support nullable names, enabled state, ordered required/ignored term lists, include-any tags, and indexer references. Empty tags or indexers mean all. TV additionally supports excluded tags, publication/air-date restriction and grace days, and a season-pack allowance. Movies reject these TV fields and permit at most one indexer. Excluded tags veto inclusion. Provider references require an indexer with a scope in the profile domain, including when the profile is disabled. Referenced tags cannot be deleted; referenced providers cannot be deleted or lose that domain scope. Ordinary same-scope provider edits remain allowed. Provider credential authentication runs before reference-conflict disclosure.

The matcher prepares all terms before opening a write transaction. The writer rechecks the domain revision and exact prepared content before committing. Literal and regex terms use the independent release-term matcher, not custom-format regex defaults. Invalid syntax rejects the write. Explicit unsupported dialect, limits and temporary matcher failures have distinct static error codes. Temporary admission, timeout, worker and state-change failures return 503. No matching runs inside a writer transaction.

Limits: 1024 profiles per domain, 200 terms per list, 2048 UTF-8 bytes per term, 4096 total term occurrences and 1 MiB term bytes per catalog, 8192 total tag/indexer memberships, 200 combined include/exclude tags per profile, 200 TV indexers or one movie indexer, 256 UTF-8 bytes per name, 128 KiB request bodies and 4 MiB catalog responses. These are native resource bounds, not claims that upstream has identical ceilings.

## Snapshot behavior

Sonarr 233 and Radarr 242 release profiles and Radarr 206 restrictions are read independently. Legacy CSV removes empty entries without trimming individual terms. Historical Radarr 206 Preferred remains private inactive archive data; no preference score is invented. Malformed encodings or invalid regex syntax fail the upload. Valid unsupported semantics/dialects and profiles exceeding supported work bounds leave the whole catalog inactive, including otherwise supported siblings. Raw source records remain archived. Temporary matcher failures abort with retryable 503 through the actual snapshot handler's error conversion.

Activation follows tags and optional provider reconstruction in the same transaction. Enabled profiles with unavailable indexers remain wholly inactive. Disabled profiles retain exact unresolved source identities; empty/all is never substituted. Native POST cannot forge unresolved references. PUT may retain an existing exact unresolved identity, remove it, or explicitly replace it with a native provider. A provider mapping added later does not silently rebind an activated unresolved reference.

An independent activation marker and durable source mappings distinguish archived pre-feature data from previously activated catalogs. Local edits, including intentional empty catalogs, prevent new backfill. Exact activated replay is idempotent. Deletion retains historical mappings, and native allocation reserves historical IDs so delete/recreate cannot impersonate a prior source identity. Any reconciliation conflict or late write failure rolls back the entire snapshot transaction. Dry runs use the same transaction and roll back.

## Editor and isolated browser verification

Profiles → Release profiles provides TV/movie create, edit and explicit delete. Names distinguish null from empty text. Each term has its own textarea and move/remove controls, preserving whitespace, newlines, duplicates and order. TV air-date, grace, pack and excluded-tag controls are absent from movie requests. Provider choices are paginated and use actual indexer domain scopes, including disabled indexers. Historical unresolved references remain disabled and unchanged until explicitly removed or replaced; removing the last reference requires acknowledgement that the profile will apply to all indexers.

Catalog revisions protect every mutation. A conflict retains the draft for reload and explicit reopening. Unknown write outcomes block repeat writes, including after navigation; readback never automatically resubmits a create, update or delete. Tag usage distinguishes included/excluded release profiles from library owners and opens the correct domain/profile. Native matcher errors display their static code; there is no browser regex engine or equivalence claim.

Use the owned fixture procedure in `docs/library-ui.md`: build/run the ignored `library_ui_fixture`, point Vite's `HRRDARR_API_ORIGIN` at its printed loopback API, and run `UI_URL=<owned Vite origin> UI_FIXTURE_JSON='<printed UI_FIXTURE JSON>' node frontend/tests/release-profiles-browser.mjs`. Use a fresh fixture: this scenario imports genuine synthetic Sonarr/Radarr backups through `/api/fixture/import-release-profiles`, then creates synthetic scoped providers and tags through real endpoints. The source backups contain no real credentials, services or media. Create the manifest's shutdown file and join the fixture; stop and join Vite afterward. The fixture has a 15-minute maximum lifetime.

Observed on 2026-09-28: 61 frontend tests passed, Svelte check returned no errors/warnings and production build passed. The real browser scenario passed both-domain exact CRUD, null/empty names, per-term text, explicit unresolved removal/cancel/replacement, pagination beyond the first provider page, included/excluded tag navigation, disabled-profile tag deletion protection, invalid/unsupported and supported-n matcher responses, stale CAS, held provider lookup followed by reload, old-domain/away-and-back response ordering, failed new-domain loads, actual tag rename during a held catalog read, and lost responses after committed POST/PUT/DELETE with explicit readback. No full Rust suite was run for this frontend unit; parent combined verification is separate.

## Not claimed

This unit does not establish release-restriction enforcement in search/RSS/grab/import decisions. TV publication grace and season-pack decisions remain consumer work. The independent matcher has explicit unsupported dialect and resource boundaries; no claim of arbitrary .NET regex equivalence is made. Tests use scratch databases, synthetic credentials and owned loopback listeners; no live providers or media are accessed. Handler classification tests exercise the exact error conversion and response status, not end-to-end runtime saturation.
