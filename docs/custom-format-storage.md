# Custom-format persistence

Migration 0034 supplies storage for both domains. It does not activate custom-format matching, snapshot import, API routes, naming or language filtering by itself.

`custom_formats` holds a domain-scoped name, an `include_when_renaming` flag, and a versioned bounded specification array. IDs are destination identities, not upstream IDs. The same name may exist in TV and movies. `quality_profile_format_scores` relates profiles to formats through composite domain foreign keys and signed 32-bit scores. Deleting a format removes its score references; deleting a profile removes its scores without deleting definitions. Scores are recalculated from current definitions/profile and file facts; no aggregate score is stored.

Specification version 1 is the serde contract in `src/db/custom_formats.rs`. Each item preserves `name`, `required`, `negate`, and a tagged `condition`. Shared conditions are release title/group, language (including `except_language`), size, source, resolution and indexer flag. Edition, year and quality modifier are movie-only; release type is TV-only (`0` unknown, `1` single episode, `2` multi-episode, `3` season pack). Numeric source/language/flag values retain their media domain. A definition has 1–64 specifications, encoded within 64 KiB; pattern text is bounded to 4096 bytes. `decode_specifications` validates structure, bounds and domain values. Consumers must compile/validate patterns using their supported regex engine before activation; this storage contract does not claim .NET regex equivalence.

The current profile policy table restricted minimum custom-format score to nonpositive values because format items were unsupported. Migration 0034 permits the signed 32-bit range while preserving every existing policy and all cutoff guards. API reachability checks for positive minimums belong to the consumer; migration does not invent scores or change a user's policy.

File facts already live in `file_metadata`: quality/revision, size, languages, release group, indexer flags and TV release type. Movies also have `movie_files.edition`. Nullable `file_metadata.original_release_title` retains the release title after rename (a path is mutable; movie-only `original_file_path` is not the same fact). Nullable `series.original_language` supplies TV catalog evidence, distinct from file audio languages. Existing rows remain unknown; NULL languages must not become a known empty array or English. No backfill guesses are made.

Snapshot identity reuses `snapshot_mappings(application,fingerprint,destination_table,source_id,destination_id)` with destination table `custom_formats`. This allows equal upstream IDs from Sonarr and Radarr to map independently. Importers must validate definitions, map scores in the same transaction, retain/report unknown settings, and introduce activation versioning only when replay behavior is delivered. Existing archival records are not automatically activated by this migration.

Owned download imports can freeze versioned comparison facts inside existing `rss_candidate_imports.provenance_json` (immutable object, total 16 KiB limit). Consumers must preserve those facts through recovery and commit them with the file association. They must not rederive original title or languages from a renamed path.

Requirements were inspected independently in pinned Sonarr `76c684e097f16ac216e6213845e5cac372774995` and Radarr `c90668a520664ad0c91812cfee57c41928ad2148`: `CustomFormats/CustomFormat.cs`, `CustomFormatInput.cs`, `Specifications/*`, `Profiles/Qualities/QualityProfile.cs`, and `*Api.V3/Profiles/Quality/QualityProfileController.cs`. This is source-established inventory, not observed upstream runtime equivalence.

Verification: `cargo test --locked --lib custom_format` exercises the actual libSQL engine: upgrade from version 33, late transaction rollback, policy/file/library preservation, domain isolation, bounds, foreign keys, snapshot mapping identity, delete semantics and reopen. No live remote storage or application workflow is claimed by these tests.
