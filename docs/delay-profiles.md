# Delay profile configuration

Each TV/movie domain owns one protected fallback and up to 1023 tagged profiles. GET `/api/v1/{tv|movies}/delay-profiles` returns a catalog revision, configuration state, availability offset and profiles in selection order (tagged first, fallback last). `/schema` returns a draft with both protocols enabled, Usenet preferred, zero delays and disabled bypasses. Draft defaults do not activate an unconfigured domain.

POST accepts `{revision, profile:{settings,tag_ids}}`; PUT `/{id}` accepts the same shape. PUT `/reorder` requires the complete list of tagged IDs and the catalog revision. DELETE `/{id}?revision=N` requires explicit current revision and rejects the fallback. Mutations return the resulting catalog; creation returns201, other successful writes200. Stale revisions return409. IDs are globally allocated, domain scoped and JavaScript-safe. Historical snapshot mappings reserve deleted IDs.

Settings include both delays (0–10080 minutes), enabled protocols (at least one), preferred protocol, highest-quality bypass, custom-format-score bypass and a signed32-bit minimum score. A preferred protocol may differ from the sole enabled protocol; it is not silently normalized. Tags must exist in the same domain, be unique across delay profiles and number1–200 for a tagged profile. The fallback has no tags. Tag detail exposes `delay_profile_ids` separately from library owner pagination; used tags cannot be deleted.

`release_delay_policies` remains the sole storage authority for fallback minutes and movie availability. Global metadata deliberately has NULL minute fields; tagged profiles store their own minutes. Existing configured policies retain `legacy_age_only` semantics, with no invented preference or bypass. Missing policies remain unconfigured. The old release-policy PUT changes only global minutes/availability and preserves all richer settings and tagged profiles. Both APIs record local intent, increment the domain revision and transactionally wake resumable pending candidates and their active parent commands. Same-value saves also record intent and may wake. Tag assignment changes use the same wake. Prepared, submitting and reconciling ownership is untouched.

The shared `select(connection, domain, owner_id)` reader uses one database snapshot and returns `Unconfigured`, `LegacyAgeOnly`, or a selected complete `Profile`. Missing fallback metadata, invalid graph ordering or incomplete joins fail explicitly. Decision writers must reread selection under their immediate transaction before committing an admission decision.

Snapshot import handles whole supported Sonarr233 and Radarr206/242 delay graphs after tag remapping. Source order becomes contiguous native positions; source fallback must actually be last. Radarr206 lacks the later custom-format bypass fields, so those remain disabled. Modern disabled bypass with NULL threshold canonicalizes to0; enabled bypass with unknown threshold stays unsupported. Movie `AvailabilityDelay` defaults to0 only when a valid Config table lacks the key; missing Config remains unavailable. Malformed JSON/null tags fail import; unknown semantic fields or protocol values preserve the whole graph as inactive archive data.

Activation requires an unconfigured, untouched destination. Exact complete graphs may reconcile as duplicates, but historical mappings must retain identity. Local edits, configured legacy policies, deleted/recreated IDs and earlier activated conflicting graphs prevent replacement. Dry runs and late errors roll back graph, provenance, old policy table and wake together. Source files and media remain untouched.

## Focused evidence

`cargo test --locked --lib delay_` passed two migration/capacity tests. `cargo test --locked --test delay_profiles` passed six HTTP/snapshot tests, including both media domains, three source schemas, explicit server joins, dry-run/rollback, local intent, archived backfill and deleted/recreated identity. The locked production check and DTO generation also passed. These are scratch databases and owned loopback listeners; no live services or media were used. The complete Rust suite also passed (321 reported passes, 319 distinct test names), along with 52 frontend tests, Svelte validation and production build. After that full run, only the two static snapshot report descriptions were corrected to mention revision/delay activation; those literal-only changes passed formatting/diff checks, and independent integration verification remains pending.

## Not claimed

This dependency exposes and preserves settings. It does not implement protocol rejection, preferred-protocol ranking, revision/highest-quality/custom-format bypass evaluation, oldest-pending overlap behavior, or an editor. Existing consumer guards remain until the separate pipeline integration is verified. It does not establish complete api046 or the full slice acceptance gate. Bounds are native operational limits; oversized catalogs are rejected and other unrepresentable settings remain explicitly unsupported. Runtime tests are recorded separately from source review.
