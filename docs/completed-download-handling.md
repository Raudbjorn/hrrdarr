# Completed Download Handling settings

`GET/PUT /api/v1/{tv|movies}/completed-download-handling` reads/saves the domain master switch. PUT requires `enabled` and the current `revision`. Reads distinguish source/native definedness, local intent, pending reconciliation (reason `pending` or aggregate `schedule_limit`, null once ready), effective scopes and scopes whose periodic observation is disabled. Master-off disables processing even for an explicit per-client true override. Equal native saves protect local intent from later snapshot activation.

Each enabled supported qBittorrent scope inherits copy-mode processing and a 60-second refresh schedule. This persists actual provider-revision authority; a GET fallback alone does not authorize imports. Configuration writes perform no network/media I/O. Provider reconciliation runs after final scopes inside the existing transaction. Provider changes still fence old receipt revisions; only current exact owned receipts can be admitted. Imported providers remain disabled and untested.

Existing scoped processing PUT remains an explicit override with strict revision/provider CAS. Its response adds `enabled_override` and `desired_enabled` alongside effective `enabled`. `PUT /api/v1/download-processing/policies/{provider_id}/{media_type}/inherit` accepts provider_revision, revision and mode to reset inheritance. It never infers permission from an omitted enabled field.

Refresh schedules distinguish inherited and explicit intent, retaining explicit intervals. `PUT /api/v1/download-refresh/schedules/inherit` accepts target, required-nullable revision and provider_revision; it resets to automatic observation. Existing schedule saves become explicit. Explicit disabled schedules remain disabled independently of processing intent. DELETE retains a hidden suppressed row; recreating a schedule requires explicit save/reset, and its internal revision does not restart at 1. A master-off change does not stop an independently explicit refresh schedule, which can still observe the queue without importing.

Visible schedules remain bounded to 64. Activation that needs more slots rolls back the initiating mutation across all affected scopes. Upgrade overflow leaves the database usable and pending: no new inherited authority from the failed batch, while valid existing explicit authority retains its provider/revision fences. Deleting/suppressing a schedule or deleting a provider retries the pending batch transactionally; still-insufficient capacity does not undo that deletion or activate an arbitrary prefix. Pending is a readiness flag, not a blanket denial of existing valid explicit authority. The reconciler uses SQL aggregate checks/set updates, never an unbounded provider vector.

Migration 0041 conservatively preserves all stored false states as explicit false, including earlier provider/scope invalidation. Existing modes and intervals remain. Historical absence inherits the changed default: old schedule deletion left no recoverable intent record, so this upgrade may resume observation for such an absent schedule. Future suppression avoids this ambiguity. Receipt and import-journal bytes are unchanged.

Sonarr 233 and Radarr 206/242 Config settings retain effective value and definedness. Missing key means true/undefined; present NULL/empty means true/defined. Canonical textual true/false is validated. Missing Config or unsupported shapes stay archived and inactive; malformed values fail atomically. Local equal saves prevent new source provenance. Dry-run and late failure roll back activation, effective policies, schedules and wake together. Source provider reconstruction never enables external clients.

Existing explicit host/domain mappings, typed library roots, current policy preflight, owned receipt identity, immutable journals and restart/retirement guards remain required. New default copy mode preserves source bytes; it does not claim upstream Auto/prefer-hardlink/move behavior. This introduces no client removal, category mutation, guessed mapping or destructive filesystem policy.

Focused evidence is in `tests/completed_download_handling.rs`, `src/db/cdh_tests.rs` and `tests/cdh_default_flow.rs`. The latter exercises both RSS and Search in both domains without policy/schedule writes, manual refresh, manual processing or injected scheduler deadlines. Execution results must accompany delivery; source presence alone is not verification.
