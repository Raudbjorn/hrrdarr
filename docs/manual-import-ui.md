# Manual import collection state

Iteration103's pure state helper is `frontend/src/lib/manual-import-state.ts`. The collection panel is implemented in `frontend/src/lib/ImportPanel.svelte`; parent App integration and runtime verification remain separate work. This document records the implemented source contracts and the required acceptance evidence, not a completed browser validation claim.

The helper uses generated `ManualImportRequest`, `Operation`, `ManualImportCommand`, `ManualImportReconciliation` and `CommandPriority` types, plus the house `Result<T>` type. It performs no network, storage, scheduling or execution. No stored state grants permission to execute automatically.

## Retained identity and intent

`ManualImportReceipt` is `{version:2,entries:ManualImportEntry[]}`. Each entry contains:

- `operationId`: canonical lowercase UUID.
- `request`: copied, frozen `{target,source,destination,mode}`, including a separately frozen typed target. Any edited request requires a new preview UUID.
- `owner`: copied, frozen `{domain:'tv'|'movies',id}` or null for unknown legacy owner. Movie owner equals movie target; TV owner is the series and is not inferred from episode ID.
- `label`: at most256 Unicode code points, no control characters or lone surrogates.
- `authorized`: whether execution/admission was explicitly authorized before transport.
- `commands`: known immutable `{id,batchId}` identities, up to100 per operation. These are references, not current statuses or proof that a batch was the original lost admission.
- `admissionUncertain`: outstanding admission uncertainty, independent of command cancellation.
- `executionUncertain`: conservative direct Execute/Resume uncertainty, persisted before every direct execution; legacy authorized receipts migrate with this true. Cancellation never clears it.
- `cancelUncertainIds`: distinct known command IDs whose cancellation outcome remains unresolved.

There is deliberately no `fresh` flag and no stored operation/command observation. Decoded and migrated identities always require fresh readback before actions. Command references, execution uncertainty or admission uncertainty require `authorized:true`. A command ID cannot belong to two saved operations. Duplicate operation IDs and malformed/unknown receipt fields are rejected.

The collection holds at most100 entries. The serialized versioned receipt is capped at2MiB of UTF-8 JSON, measured after escaping on write and before parsing on read. Paths are at most4096 UTF-8 bytes, absolute, non-root, normalized without empty/dot/dot-dot components, NUL or lone surrogates. Normalized filenames containing tabs/newlines or other non-NUL controls are retained exactly, matching the backend path contract; label/message text keeps its separate control-character policy. IDs must be positive safe integers. Filesystem identity and permission validation remain server responsibilities. Overflow returns an error; nothing is silently truncated or evicted. The caller must also handle browser quota/security failures. Do not issue admission when the identity/uncertainty record could not first be retained.

## Exported helpers

All validators/serializers return `Result<T>` (`{ok:true,data}` or `{ok:false,error}`); the one simple intent update returns a new entry directly. Existing objects are not mutated.

| `markExecutionUncertain(entry)` | Return a new entry with authorization and direct execution uncertainty true before every Execute/Resume POST. Persist first. |

| `resolveCancelUncertain(entry,commandId,value)` | Require matching terminal command readback; clear only that command's cancellation uncertainty. Running/queued/retry_wait readback leaves the outcome unresolved. Preserve authorization, execution uncertainty, admission uncertainty and other command cancellations. |

Command attempts are0–3. Queued requires attempt0/no start; running, retry_wait and succeeded require a positive attempt/start; active states have no completion time, terminal states require one; failed/retry_wait require an error and other statuses forbid one; retry_wait requires attempts below3. Failed and cancelled with attempt0 remain valid. Enum values must be actual strings; arrays and objects are never coerced.

The generated baseline predates iteration101. The operation validator therefore accepts either both recovery properties absent (returns `recoveryProjectionKnown:false`) or both present and valid. One missing field, malformed/unknown diagnosis, contradictory complete/recovery state, or recovery requested without any error/marker is rejected. After101 integration the generated Operation includes these fields; the compatibility check remains useful for old receipts. The caller must not interpret absent recovery projection as healthy, active or resumable. Known diagnostics are the existing45 role/kind/boundary codes plus `unresolved_attempt`; unknown diagnostics fail closed.

The reconciliation endpoint is `POST /api/v1/manual-import/commands/reconcile` with `{operation_ids}` (1–100 distinct UUIDs), returning an ordered array of generated `ManualImportReconciliation`: `{operation_id,operation:Operation|null,active_command:ManualImportCommand|null}`. It is a snapshot, not a reservation, historical batch reconstruction, or proof that an outstanding POST has settled. Known terminal command IDs are fetched separately. This helper validates results; transport wrappers remain in `api.ts`.

## Caller responsibilities and uncertainty

Capture entries, selection and priority before each request and reject responses from an old owner/request generation. Reconciliation returns observations without altering saved intent. Freshness is ephemeral and must be invalidated after mutation, reload, navigation races and cross-tab changes. No helper decides that a clean preview can be automatically re-admitted or executed.

A lost admission can later enqueue after another observed command is cancelled. Cancelling one command therefore does not clear outstanding admission uncertainty. `recordKnownCommand` also preserves that uncertainty: observing a current command does not prove which pending request created it. Any later settlement of admission uncertainty must be an explicit caller decision backed by the actual request outcome or final operation state; do not clear it merely because one snapshot has no active command.

A failed command can remain failed after explicit same-operation recovery completes. Keep the terminal command result and actual operation result distinct. Completed operations require no Resume. Active unresolved markers forbid Resume; recovery permission requires the current101 projection plus reconciled command ownership. An explicit same-UUID Resume is allowed despite older admission uncertainty when the fresh operation has recovery_required true, durable marker/error, and no active wrapper: that durable state rejects late queue admissions. This depends on the101 command-start permit repair; uncertainty provenance is retained. Existing saved authorized clean previews must retain the explicit lost-direct-request Resume workflow, never become an automatic batch submission.

Selection conflict checks concern captured request paths and typed IDs. They cannot prove paths do not alias on disk or that another tab has not changed the journal; server checks and permit ownership remain authoritative. These helpers do not revoke outstanding requests, implement durable idempotency, reconstruct lost source/destination fields from Operation, or restore deleted server history.

## Panel workflow and parent contract

The panel retains a mixed TV/movie collection and an independently captured current form. Props are `target`, `label`, optional `owner:{domain,id}|null`, optional `active` (defaulttrue), optional `relatedWrite` (defaultidle), optional `onwrite(state)`/`ondirty(boolean)`, and `oncomplete({operationId,target,owner})`. The completion callback only follows a validated actual complete operation with the captured typed target/owner, at most once per retained operation per mount. It never follows a command success alone. Old no-argument callbacks remain assignable, but parent integration should scope refreshes by the event.

The parent must keep the panel mounted across workspaces, hiding it and changing `active` to pause polling. It passes its related write state excluding this panel's own transient mutation state, preventing a self-lock. GET reconciliation/history reads do not report write-busy. The panel owns a beforeunload guard for its raw draft, mutation and unresolved unsafe-to-forget state. Collection rows are not a navigation lock; the parent must allow collecting another target. A changed incoming target cannot silently reassign an existing form: “Keep current draft” and “Discard form and use …” are explicit choices, with confirmation for a populated form.

`Preview import` validates/captures one request and appends its actual preview UUID without authorizing transfer. The panel checks fresh operation/active-command state before offering `Execute import`, `Resume import`, or queue admission. Selected admission is available as `Queue selected imports`; uncertain selected entries instead require the explicit `Authorize selected queue again` action (or per-row `Authorize queue again`). Both reuse the same UUIDs, validate selection conflicts, capture priority, and persist admission intent before POST. A known rejection settles only this new request; older uncertainty remains. A valid202 is checked for exact ordered membership/priority/batch and stored with its command references. No automatic mutation retry exists.

Direct execution always persists `executionUncertain:true` before POST, including explicit resume. It remains conservatively recorded even if a pre-effect failure may have occurred. Fresh complete journal state fences late effects, without asserting that an older HTTP response was recovered. Cancellation is individual, available for a fresh queued/retry_wait command whose operation remains an unmarked preview; it preserves both admission and execution uncertainty. A failed historical wrapper and subsequently completed operation remain separately visible. Diagnostics use the101 `pathDiagnostics` helper and appear independently of generic error code.

If every command with unresolved cancellation has a fresh404 detail response, a fresh operation and ownership snapshot with no active wrapper can permit an explicit new queue admission or direct action on the same operation UUID. Existing clean-preview and recovery checks still apply. A deleted immutable command cannot receive a late cancellation against the new wrapper, but its absence proves neither that cancellation succeeded nor that the import had no effects. Keep `cancelUncertainIds` and other uncertainty unchanged; missing history does not permit forgetting an incomplete operation.

Local removal is limited to fresh completed operations with no active wrapper; never-authorized clean previews; or clean previews with every known command freshly cancelled, no active wrapper, and no admission/execution/cancel uncertainty. Completed receipts can be explicitly removed even when request provenance remains unknown because the journal fences later effects. Removing an unexecuted/cancelled preview does not delete its server preview. Missing operation, missing cancellation history, or unresolved authorization cannot be silently forgotten to free capacity.

Storage uses `hrrdarr.import.collection.v2`; the old `hrrdarr.import.receipt.v1` migrates only through validated identity capture, preserving authorization and requiring fresh server readback. No operation observation is restored as fresh. Another tab changing either receipt blocks new authorization and asks for export/reload rather than overwriting its data. Storage failure before authorization prevents the POST. Failure after a response preserves identities in memory and offers a bounded readonly JSON receipt plus download (or an explicitly labelled bounded identity-only list if the full receipt exceeds its byte budget); export includes only validated identities in this tab, not unreadable/newer browser data. Browser quota/security and corrupted receipt failures remain explicit. Export is recovery evidence, not an execution or cancellation action.

Polling starts from5seconds, backs off to60seconds, pauses when hidden/inactive, and has one reconciliation in flight over at most100 UUIDs. Historical known-command readback runs at most4 parallel GETs and at most100 IDs per cycle, prioritizing unresolved cancellation then rotating through remaining references. Pruned history is shown as unavailable, not failed execution or nonadmission. Generation checks discard reads overtaken by a mutation/visibility change. Fresh reconciliation can enable actions while unrelated historical reads finish; a mutation invalidates the earlier read generation. Fully settled completed rows stop polling once known command observations are settled/unavailable. Removing a row drops its cached observations as well as its receipt.

## Required integration and browser acceptance

Parent integration must apply accepted101 diagnostics/types/command-start authorization repair and102 file-editor state first, regenerate API contracts, then run frontend type/build checks. The panel intentionally imports `./pathDiagnostics`; it must arrive through101 integration rather than a copied parallel implementation. Parent completion handling should invalidate only the affected library owner, retain unsaved settings/file metadata, and defer related file refresh while editing/busy/uncertain. Unknown legacy TV owner should refresh only safely identifiable current episode ownership or the domain list.

Preserved visible controls include `Preview import`, `Execute import`, `Resume import`, `Check status`, `Edit unexecuted preview`, and `Prepare another import`. Source/destination are now textareas so legal newline/tab filenames survive editing; label-based browser selectors continue to work. Rows have an accessible `Import <captured label>` article name; multiple-row tests should scope controls to that row. The panel no longer disappears after one preview and shows a collection-wide Check status control. Legacy localStorage assertions must target migrated v2 identity/intent, not a saved Operation object. “Prepare another import” removes only that completed retained row; other collection rows survive.
