# Metadata lookup and selected add

The native TV and movie library lookup routes use the pinned references' public catalog wire contracts. These are independently implemented clients, not direct TVDB/TMDB SDKs or a claim of upstream runtime equivalence.

| Domain | Fixed service base | Requests |
| --- | --- | --- |
| TV | `https://skyhook.sonarr.tv/v1/tvdb/` | `search/en?term=…`, `shows/en/{tvdb_id}` |
| Movies | `https://api.radarr.video/v1/` | `search?q=…`, `movie/{tmdb_id}`, `movie/imdb/{imdb_id}` |

Titles use URL query encoding. TV accepts `tvdb:`/`tvdbid:` identifiers; movies accept `tmdb:`/`tmdbid:` and `imdb:`/`imdbid:` identifiers. Numeric identifiers must be positive signed 32-bit integers. IMDb identifiers must be `tt` followed by 7–10 digits, with a nonzero numeric portion. Whitespace around a prefixed identifier is ignored. Wrong-domain known prefixes are rejected. Other titles containing a colon remain titles. Pasted website URL recognition and other TV identity search variants remain incomplete.

Lookup returns an array of `{media_type, external_id, title, year, imdb_id}`; `media_type` explicitly namespaces `external_id` as TVDB for TV and TMDB for movies. A catalog 404 becomes an empty lookup result, but a selected detail request returns native 404. Selection uses the domain-specific numeric ID and refetches canonical details; lookup data supplied by a caller is never trusted for insertion. See [library API](library-api.md) for native routes, selected-add bodies, atomic persistence and monitoring rules.

TV details include series TVDB identity/title, nullable year derived from `firstAired`, nullable IMDb identity, declared seasons and the complete returned episode catalog. Each episode retains TVDB identity, season/episode numbers, title, nullable local air date, UTC instant, absolute episode number, runtime, overview and finale type. Episode IDs and season/episode pairs must be unique; episodes must reference a declared season. Missing seasons or episodes arrays reject a detail response; explicitly empty arrays are valid. Missing optional facts remain null. Air dates must be valid `YYYY-MM-DD`; UTC instants require RFC3339 and normalize to the existing canonical UTC storage format without losing subsecond precision. More than nine fractional digits and leap seconds are rejected. Series IMDb identity is returned by lookup/details but is not yet persisted by the series library schema.

Movie details currently retain TMDB/IMDb identity, title and nullable year. A source year of zero means unknown. Alternate/localized titles, movie release dates, runtime, credits, ratings/certification, collections, recommendations, artwork and extras remain required future work. TV series enrichment beyond these fields, NFO output, direct TVDB/TMDB/TVMaze providers and scheduled refresh are likewise incomplete; unknown response fields are ignored and never presented as implemented enrichment.

The client reuses the existing provider HTTP transport: no proxies, automatic retries or redirects; bounded concurrency, per-service serialization and cooldown, 10-second request timeout and 30-second operation deadline. Responses are limited to 1 MiB including unknown fields. Lookup is capped at 100 entries, TV details at 1,000 seasons and 10,000 episodes; oversize data rejects the whole response instead of creating a partial catalog. These limits may reject large legitimate catalogs. No real catalog response-size survey was performed, so this is an explicit delivery limit, not evidence that every series fits.

No caller supplies a URL or credential. Normal startup uses the fixed HTTPS bases. `MetadataClient::with_origins` permits those exact bases or canonical `http://127.0.0.1:<nonzero-port>/` roots for isolated test injection; userinfo, non-root paths, queries, fragments and alternate hosts are rejected. Errors return static native messages without upstream URLs, bodies or headers; rate limits expose only a bounded `Retry-After` value. No database transaction is held during catalog requests.

Paths after `NzbDrone.Core` are relative to that source directory. Source inspection establishes requirements only; no upstream code was copied or translated.

Verification: `cargo test --locked metadata::tests::catalog_transport_validation_and_bounds` exercises owned local HTTP fixtures for query encoding, typed IDs, nullable facts, UTC normalization, HTTP failures, bounded responses, cooldowns and origin validation. `tests/metadata_lookup.rs` connects lookup and selected add to real native library/import endpoints. No live metadata services, real exported catalog fixtures, filesystem media discovery or provider runtime equivalence were tested.

TV detail responses now expose nullable `original_language`, using TV catalog identities (Arabic 26, for example; movie Arabic is 31). The SkyHook wire field is `originalLanguage`, an ISO-code string, as established from pinned Sonarr `76c684e097f16ac216e6213845e5cac372774995` `MetadataSource/SkyHook/Resource/ShowResource.cs`, `SkyHookProxy.cs`, and `Parser/IsoLanguages.cs`. Known two/three-letter codes and supported regional forms such as `pt-BR`/`es-MX` resolve through the shared domain language catalog. Display names and numeric/object language payloads are not this source's wire contract. The shared name decoder is available separately for producers whose contracts use names.

Selected TV add persists that fact atomically with the library/episode graph. Missing, null, empty or unrecognized codes produce no language evidence: no English default is invented. Refresh retains an existing language when no new evidence arrives; a known new language replaces it. This intentionally avoids the reference's English fallback. Malformed types, invalid characters and oversized values reject the response before mutation. Explicit unknown metadata does not clear a prior known fact. Shared movie decoding retains its existing alphabetic two/three-character wire validation and IDs, while now recognizing known three-letter aliases through the same catalog.

`tests/metadata_lookup.rs::tv_original_language_survives_lookup_add_refresh_failure_and_reopen` uses an owned loopback producer and scratch database to verify add, updates, missing/unknown metadata, rollback, reopen, file ownership and monitoring preservation. This supplies catalog language evidence; audio-language inference and Original-policy matching are separate consumers, not established by this metadata test.
