# Native release decisions

`POST /api/v1/release-search` performs an explicit, read-only user search. The request supplies `provider_id`, `provider_revision`, a typed existing `target` (`episode` or `movie` with `id`), `offset`, `query_index`, and `limit` (1–100). Library metadata supplies the indexer query; callers cannot inject replacement library identities or an automation context. Responses contain safe release metadata, parsed facts, typed matches and rejection reasons. Private GUIDs, locators and provider credentials are not public fields. Continuation is the indexer's bounded `next_query`.

The library detail UI also provides **Search and download** through the [durable search commands](search-commands.md). Choose an indexer and client, then either retain results for an explicit selection or request automatic selection. The search command and its download receipt have separate statuses: completing a search does not prove the client accepted the download. Unknown write outcomes lock further actions until explicit status readback; an unaccepted command can be retried with the same request UUID. Unused terminal search history can be removed to free retained-result capacity.

The same evaluator is consumed by durable RSS using server-controlled `Rss` context. Matching checks media categories, external identity conflicts, library identity and numbering before quality, monitoring, existing files, availability, delay and blocklist title checks. A matching numeric episode ID and movie ID never identify the same target. Missing configuration or facts produce explicit rejection rather than invented defaults.

`GET /api/v1/release-policies/{tv|movies}` returns the configured policy or `null`. `PUT` stores `torrent_delay_minutes` and `usenet_delay_minutes` (0–10080), and `availability_delay_days` (−365–365; TV must use zero). Background evaluation requires this explicit configuration. Delayed releases use publication time plus the selected protocol delay. Movie availability reads actual release dates at evaluation time, including the cinema-plus-90-days fallback when both home-release dates are unknown. User search bypasses availability and configured delay; identity, deleted catalog state, quality and blocklist checks still apply.

Complete [delay profiles](delay-profiles.md) select the first matching tagged profile or domain fallback. Disabled protocols reject even explicit user search. Preferred-protocol revision, highest-allowed-quality and configured CF-score bypasses retain all other vetoes. TV revision delay bypass requires PreferAndUpgrade; the movie predicate can allow a CF upgrade with an exact revision increase under DoNotPrefer. Highest allowed quality is not the cutoff quality. Legacy minute-only settings retain age-only semantics without an invented preference or bypass.

Qualities use the existing domain catalog and ordered profile groups, not catalog ID ordering. Higher quality can upgrade before the quality cutoff; equal-quality upgrades without a preferred superior factual revision require a strictly higher current custom-format score, an unmet format cutoff, and the configured minimum score increment. Every candidate must meet the profile minimum score. Size limits use MiB per minute with known runtime. Movie Any (`language_id: -1`) imposes no language restriction. Original (`-2`) resolves the stored movie original language; concrete policies compare explicit indexer language names/ISO codes or recognized technical-suffix language tokens. Missing evidence or an unknown original language rejects with `language_not_wanted`. These are provider/parser facts, not media-stream verification. The same policy applies at grab and downloaded-file import. Stored policies are never rewritten. Revision-aware upgrades use the domain revision policy and factual `{version, real, is_repack}` evidence. REAL/version comparison precedes custom-format scores; repack identity alone does not establish superiority. Unknown historical revisions are not fabricated. RSS proper upgrades enforce the application-local seven-calendar-day boundary; explicit user search retains its age exception, while repack and anime group checks remain applicable. Every affected current file must permit replacement.

The independent token parser recognizes standard S/E numbering, repeated episode tokens, season packs, daily dates, simple absolute anime numbering, movie year, common WEB/HDTV/Bluray qualities and a small edition vocabulary. Contradictory sources or resolutions reject. Unrecognized technical suffixes/numbering remain unknown. This is not a 95% parser coverage claim. Television aliases and identity types other than stored TVDb, advanced packs, scene mapping search queries, full language/codec/audio/group parsing, full edition recognition, full release restrictions and complete upstream delay-profile semantics remain incomplete. Multi-episode parsing does not imply safe multi-episode qBittorrent submission.

Work is bounded: 1024-byte titles, 10000 scanned library rows or episodes per match, 64 movie aliases, 1 MiB public result, 40-second search deadline and five-second policy I/O deadlines. Exceeding a scan limit fails rather than claiming a unique match from truncated data. This serial scan is a deliberate initial ceiling; indexed normalized titles and batched evaluation belong with larger-library throughput evidence.

Runnable evidence: `cargo test --locked --test release_decisions` exercises both-domain decisions and the real HTTP search consumer against an owned ephemeral Torznab fixture; parser tests exercise independent TV/movie title corpora. These checks do not prove live indexer compatibility, full parsing parity or completed download import.


Custom-format definitions and profile scores are native domain-scoped settings. See [custom formats](custom-formats.md) for bounded matching, durable facts and remaining scope.
