# Native custom formats

`/api/v1/{tv|movies}/custom-formats` supports list/create, `/{id}` detail/replace/delete, `/bulk` update/delete, and `/schema` condition templates and grouped presets. Bulk mutations are atomic. Domain-scoped profile `format_items` contain signed scores; newly added definitions read as zero without dropping prior scores. Profile minimum reachability sums positive scores only. Deleting a definition cascades only its score rows.

Specifications group by condition type: every required member and at least one member of each type must match, and every type must match. Empty definitions are invalid. Size uses `(minimum, maximum]` GiB; year endpoints are inclusive. Movie release-title matching simplifies the movie identity prefix while retaining technical text; TV uses the release title. Downloaded filenames are additional title evidence. Language null is unknown and never matches, including negation; an explicit empty list is distinct. Original uses the catalog language when known; otherwise custom-format conditions retain the Original sentinel comparison (including Except/Negate), whereas the movie profile requires a known original language. Domain language identifiers come from the shared native catalog.

Search and RSS evaluate current definitions/profile, rank equal-quality releases by score, and re-evaluate before client submission. The prepared-to-submitting transaction freezes versioned factual evidence with private payload deletion. Legacy NULL evidence stays unknown. Downloaded identity is checked independently; immutable provider flags/languages survive private payload removal, naming, import journal recovery and final file metadata. Existing files are scored from current definitions and original release title, then original filename, then current filename; saved scores never authorize upgrades. Fresh transaction checks require an exact previously evaluated catalog/facts/score fingerprint, avoiding regex work while holding the SQLite writer lock. Settings or file changes invalidate that fingerprint and reject the operation.

Explicit manual target mappings retain their existing override behavior, including arbitrary filenames. They persist the original filename and only recognized parser facts for future comparisons; they do not become automatic name-matching decisions.

Matching uses pinned fancy-regex 0.19.2 with lookaround/backreferences, case-insensitive matching, bounded pattern/input/catalog sizes, AST depth/repetition work limits, 100,000 backtracks, bounded delegated expression memory, and two admitted blocking workers. Absent expressions and recursive calls are rejected. Runtime regex failure is an explicit error, never a no-match. A ten-second caller deadline does not forcibly terminate a blocking worker; admission remains held until it finishes, with elapsed checks between specifications. This is a supported bounded subset, not universal .NET regex compatibility.

## Editor and presets

The Custom formats workspace provides separate TV/movie lists and typed create/edit/delete forms. Pick a condition kind, add its default template or copy a preset, then edit its parameters, name, Required and Negate flags. Every supported condition kind has typed controls; available numeric choices come from the same domain schema as the API. Clone format and Clone condition produce independent editable copies. Native JSON import/export preserves names, flags and typed conditions; import checks the bounded document structure before explicitly applying a new draft, and Save validates expressions before persistence. No JSON import writes automatically. Delete requires explicit confirmation and removes that format's scores, never media. Bulk mutations remain available through the API; the editor handles one definition at a time. Quality-profile score editing is a separate workflow.

`CustomFormatSchema.presets` groups `{label, specification}` entries by condition kind. Six release-title presets are supplied: x264, x265, Simple Hardcoded Subs, Hardcoded Subs, Surround Sound and Preferred Words. Their expressions are independently authored from the pinned controllers' observable requirements. Codec and simple subtitle presets intentionally match substrings; Preferred Words matches the default terms SPARKS and Framestor as words. They are editable starting points, not media-inspection results.

The JSON format selector supports both the native DTO and the Sonarr/Radarr community document: `name`, `includeCustomFormatWhenRenaming`, and `specifications` with `name`, `implementation`, `negate`, `required`, and a `fields` object. Explicit mappings cover all eleven supported implementation kinds across their valid TV/movie domains. Export omits IDs and display metadata. Import discards only those known identity/display fields; unknown semantic fields, condition implementations or options reject the entire definition. The chosen library controls numeric enums; the document never selects a domain or native identity.

Missing numeric fields use the pinned source defaults of zero, missing boolean flags use false, and missing regex values remain null. Native example defaults are never substituted. Valid zero/false values survive; incomplete size/year/flag/regex conditions fail validation as they also do upstream. Documents and exports are bounded to 72 KiB. Applying creates a reviewable draft without a request; only Save writes after server validation. Expressions outside the native regex dialect can therefore be edited before saving, but cannot become persisted definitions until accepted by the server. Pure tests cover every supported implementation, omitted defaults, metadata removal, wrong-domain values, malformed/unknown documents and bounds; the real browser imports, edits, exports and saves community documents in both domains while asserting that Apply alone creates no row.

Each saved condition also appears as `format: condition` in its domain and kind. The display label may contain 202 Unicode characters; the copied condition retains its original valid name (maximum 100 characters). Copies are independent values: editing or deleting the source does not alter a copied definition. The schema reads the existing bounded catalog and is refreshed after mutations. Unknown write outcomes block further edits until explicit reload; a confirmed save followed by a failed refresh is reported separately. Domain changes discard the current unsaved draft and stale responses cannot replace the selected domain.

Verification uses the real HTTP handlers in `tests/custom_formats.rs`: both-domain preset validation, independently chosen positive/negative token corpora, long labels, saved-condition grouping/copy isolation, deletion refresh, and bounded regex syntax cases. Regex dialects differ: `(?R)` is a Rust CRLF-mode flag here, not a recursive call; unsupported call syntax such as `(?0)` is rejected. Successful compilation does not establish .NET expression equivalence.

For the real editor regression, run the owned [library UI fixture](library-ui.md#runnable-isolated-browser-verification), point Vite at its printed API origin, then run `UI_URL=http://127.0.0.1:<vite-port> node frontend/tests/custom-formats-browser.mjs`. Use a fresh fixture with empty custom-format catalogs. The scenario covers both-domain create/update/copy/delete, explicit cancellation, server validation, typed condition controls, native and community JSON roundtrips and clone independence, long labels, movie-only kind reset, failed post-save refresh and delayed domain responses. `npm --prefix frontend test` separately checks helper routing, exact payloads and errors. All fixtures use isolated databases and loopback listeners; no live services are contacted.

## Not claimed


Supported snapshot definitions and profile graphs are reconstructed by the snapshot importer; see [snapshot contracts](snapshot-import.md). A complete profile/default/delete editor and custom-format naming inclusion remain required follow-up work. Parser language/group recognition is intentionally limited and does not inspect media audio streams. Full proper/repack revision policy, upstream parser coverage and full custom-format parity are not claimed. This change adds fancy-regex and its bit-set/bit-vec dependencies, bounded process-local score cache state, native definition/score settings and durable factual receipts.
